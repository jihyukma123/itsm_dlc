> R-01 Reviewer note: `app/release_assurance/catalog.py` now maps the 73 IDs to real behavior selectors, but `app/release_assurance/evidence.py:310-317` persists and trusts one caller-supplied raw JUnit string instead of 73 closed `VerificationEvidence` records with procedure, safe counts, evidence digest, and execution time. `tests/test_release_assurance_evidence.py:68-145` demonstrates that hand-built XML containing the expected selector names is sufficient to obtain `release_ready`; no test command execution or command digest is bound to those results. Exact selector naming is therefore fixed, but authoritative per-check execution evidence is not.

> R-02 Reviewer note: Caller authority moved from an explicit terminal-state flag into arbitrary evidence JSON, so the release decision remains forgeable. `tests/test_release_assurance_evidence.py:68-145` synthesizes passing JUnit, regression counts, coverage numbers, boundary counters, documentation status, and an empty defect list without executing those checks, and `EvidenceRepository.finalize` accepts them as `release_ready`. The coverage record validated at `app/release_assurance/evidence.py:353-361` contains only caller-provided counts and omits the required frozen-input digest, approved base, per-unit bindings, tool version, command IDs/digests, and exit statuses; regression evidence likewise is checked against a baseline receipt that the public `publish_baseline_receipt` API accepts from arbitrary dictionaries. Closed keys and current revision labels do not authenticate that the mandatory commands ran. Finalization must consume evidence produced by the actual runners/gates, validate their command and immutable-input provenance, and reject synthetic records rather than merely validating their shape.

> R-03 Reviewer note: Explicit U4 mode now enforces the four unit names and `u4_union_changed_lines` consults every supplied baseline. However, neither `build_binding` nor `freeze_inputs` authenticates a baseline as the named unit's attempt baseline or rejects reuse. The finalized `.release-assurance/coverage/u4/coverage-inputs-v3.json` binds the same `baseline-6532efa31d44.tsv` path and digest to U1, U2, U3, and U4, so the reported 86.02% denominator is not backed by four unit-owned attempt baselines. Require unit-bound baseline provenance and reject duplicated or mismatched attempt baselines; persist the complete frozen binding and gate command evidence in the finalized coverage record.

> R-04 Reviewer note: `publish_baseline_receipt` now uses an owner lock, a pending directory, fsynced atomic record writes, and pending-to-final rename, and baseline/final snapshots use the same `app` and `scripts` roots. The focused tests exercise concurrent-writer refusal, root parity, and absence of a partially visible final locator after a simulated publication crash.

> R-05 Reviewer note: README section 6 now names the implemented `app/ticketing/*` modules, delegated-capability path, and current registry tests; the obsolete `app/agent/tools.py`, undecided token path, and `test_agent_has_no_tools` guidance is gone.
