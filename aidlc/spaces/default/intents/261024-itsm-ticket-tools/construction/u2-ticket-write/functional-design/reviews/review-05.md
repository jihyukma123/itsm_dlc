> R-07 Reviewer note: `retryable_no_apply`와 claim 진입 상태는 추가됐지만, refresh 자체의 durable ownership 또는 `refresh_used` 증거가 없다. 현재 순서는 refresh 후 새 CAS claim이므로 둘 이상의 caller가 동시에 refresh할 수 있고, refresh 성공 후 claim 전 crash에서는 재시작 caller가 이미 사용된 refresh를 구별하지 못한다. 따라서 계약의 “credential refresh allowed once”와 finding이 요구한 crash·경쟁 caller 동작은 아직 구현 결정에 맡겨져 있다.

> R-08 Reviewer note: Ledger가 `claim_id`와 `claim_deadline_at`을 보존하고, deadline 전 takeover 금지와 expected claim ID CAS 기반 `begin_stale_claim_reconciliation`을 정의하며, crash/concurrency 표가 active claimant와 recovery winner·loser 및 전역 attempt ceiling을 명시한다.

> R-09 Reviewer note: FD-U2-01, BR3.2, entity constraint가 모두 이전 evidence 없는 `prepared` row의 expected-state terminalization, 이전 U1 pending invalidation, 새 ledger commit, 새 pending publish 순으로 일치한다. 각 경계의 crash와 concurrent confirm도 stale row가 POST 권한을 얻지 못하도록 정의됐다.

> R-10 Reviewer note: `record_definitive_outcome`에는 expected claim ID와 stale-current-state 결과가 추가됐지만, 같은 authoritative repository block의 `mark_outcome_ambiguous` output은 여전히 `ambiguous`만, `record_reconciliation` output은 completed/retryable/ambiguous만 허용한다. 아래 concurrency invariant는 stale transport·reconciliation writer가 current state를 반환한다고 하므로 operation output 계약과 충돌하며, ambiguous 또는 reconciliation 늦은 writer의 no-op 결과 shape가 아직 구현 가능하게 닫히지 않았다.
