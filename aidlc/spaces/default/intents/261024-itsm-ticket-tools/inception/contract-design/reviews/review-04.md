> R-04 Reviewer note: `TicketCursorBindingV1` now requires `query_serialization_version` and `canonical_normalized_query_json`, but `TicketCursorRepositoryV1.issue` still accepts only capability, hash, and upstream cursor. The repository therefore cannot populate the required canonical query fields from its declared call and cannot guarantee exact reconstruction from `continuation_ref`.

> R-05 Reviewer note: Catalog transport is split into endpoint-specific `list_services_once` and `list_models_once` calls; each Gateway call is one HTTP attempt, while selector matching and all multi-call/retry policy are owned only by `TicketOperations`.

> R-07 Reviewer note: `SafeTicketDetailV1` is now a single U1-owned common schema used by C-01, imported by C-02, and referenced by the read contract, so U2 and U3 do not own competing definitions.

> R-08 Reviewer note: The contract, components, ADR-003, and `unit-of-work.md` now name the cursor and presentation records, but `unit-of-work-dependency.md` still describes U1's persistence ownership as only the pending-mutation migration and omits both repository interfaces from its integration-point table. In addition, `ticket_tools_common_v1` groups session-database tables with `ticket_message_presentations`, which components place in the separate Agents SDK history database, without defining how that namespace is applied per database. U1 migration ownership and U2/U3 no-edit boundaries therefore remain ambiguous in the complete upstream set.

### Summary

The endpoint split, retry ownership, shared ticket-detail schema, and earlier tool/auth/PATCH/history corrections are now sound. The design remains not ready because the cursor issue API cannot create its own required binding, storage ownership is still inconsistent across upstream artifacts and database locations, and the common pending-mutation schema has conflicting create/update definitions.
