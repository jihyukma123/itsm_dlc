> R-01 Reviewer note: C-03A now defines every referenced custom V1 type, separates `TicketWriteDraftV1` from resolved `TicketCreateInV1`, supports catalog ID/name and timestamp/`now`, and carries `CurrentTurnEvidenceV1` through the runner context into the confirmation bridge.

> R-04 Reviewer note: `ticket_cursor_bindings` stores only `normalized_query_hash`, not the normalized filter/sort/limit values, while `resolve_once` promises to return `normalized_query`. Because a continuation call forbids all query fields, the server cannot reconstruct the original request from the declared row.

> R-05 Reviewer note: Ticket calls are now single-attempt at the Gateway, but `read_catalog_once` still accepts service/component/model selectors and returns a fully resolved catalog result. The authoritative API exposes services and models through two separate endpoints, so this method cannot both resolve a draft containing a model and honor `http_attempts_per_call: 1`; it also leaves name matching inside the transport boundary.

> R-06 Reviewer note: C-03 now defines the companion-table location, conversation lock, sequence-plus-text-hash correlation, verified atomic metadata row commit, old-row fallback, restart restoration, clear ordering, and U4 contract tests.

### Summary

The revised design fixes the tool DTO, authentication, PATCH, and presentation-history mechanics. It is still not implementable without architectural choices because cursor continuation cannot reconstruct its bound query, catalog resolution contradicts the single-attempt transport boundary, and two cross-unit/storage ownership conflicts remain.
