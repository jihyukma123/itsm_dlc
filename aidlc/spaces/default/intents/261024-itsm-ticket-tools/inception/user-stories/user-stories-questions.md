# 사용자 스토리 계획 질문

## Context

승인된 요구사항에서 다음 사항은 이미 결정되어 다시 묻지 않는다.

- 주요 사용자는 일반 사내 사용자와 서비스 데스크 담당자이며, 권한·가시성은 ITSM API가 최종 판정한다.
- `ticket_read`, `ticket_write`, `ticket_update` 세 도구와 공통 보안·세션·오류 경계는 모두 Must Have다.
- 전달 순서는 공통 안전 경계, `ticket_read` walking skeleton, 등록, 수정, 전체 회귀·문서 검증이다.
- 새 화면 없이 기존 대화 입력과 텍스트 결과·확인·복구 흐름을 유지한다.
- 등록·수정은 현재 사용자와 정확한 대상·필드·값·version에 결합된 명시적 확인 뒤에만 실행한다.
- 실제 OpenAI·ITSM을 호출하지 않는 테스트, 기존 37개 테스트 통과, 변경 코드 80% line coverage와 README 갱신이 필요하다.

## Story Plan

- 형식: `As a [persona], I want [action], so that [benefit].`
- 인수 조건: 안정적인 `AC{group}.{story}.{sequence}` ID와 Given/When/Then 형식
- 우선순위: MoSCoW. 승인된 첫 버전 범위는 Must Have로 유지하고 범위 밖 기능은 Won't Have로 명시
- 품질 기준: 각 스토리에 관련 보안·권한·오류·접근성 기준을 포함하고 `FR`·`NFR`에서 `US`로 양방향 추적 가능하게 작성
