# ITSM 티켓 도구 범위 정의

## 목적과 근거

이번 기능의 목적은 기존 ITSM Assistant 사용자가 대화 흐름을 벗어나지 않고 티켓을 조회·등록·수정하게 하여 반복 업무 시간을 줄이는 것이다. 범위는 승인된 `intent-statement.md`의 사용자 문제와 성공 기준, `feasibility-assessment.md`의 진행 조건, `constraint-register.md`의 계약·보안·회귀 제약을 따른다.

첫 릴리스는 새 Agent, 별도 서비스 또는 새 화면을 만들지 않고 현재 Assistant의 사용자 경험을 확장한다. 로그인 사용자의 기존 ITSM 권한과 티켓 가시성은 그대로 유지되어야 하며, 실제 데이터 변경은 사용자가 최종 내용을 확인한 뒤에만 실행한다.

## 대상 사용자와 가치

- 일반 사내 사용자는 자연어로 자신에게 보이는 티켓을 찾고 상세 내용을 확인할 수 있다.
- 일반 사내 사용자와 서비스 데스크 담당자는 필요한 정보를 대화로 모아 티켓을 등록하거나 허용된 내용을 수정할 수 있다.
- 모든 사용자는 별도 ITSM 화면으로 이동하지 않고 대표 조회·등록·수정 업무를 끝낼 수 있다.
- 권한과 가시성 판단은 기존 ITSM 시스템이 담당하므로 Assistant가 사용자의 권한을 확대하지 않는다.

## 범위 내 기능

### Must Have

1. **공통 안전 경계**
   - 현재 로그인 사용자의 서버 측 세션과 사용자 위임 권한으로만 티켓 업무를 수행한다.
   - ITSM API v2의 권한·가시성 판단과 오류 의미를 유지한다.
   - 액세스 토큰, 클라이언트 secret, OpenAI API key를 모델 입력, 도구 결과, 로그 또는 오류 응답에 노출하지 않는다.
   - 기존 사용자 전환, 세션, 대화 이력, 고정 모델 설정, 화면과 API 동작을 유지한다.

2. **`ticket_read`**
   - 티켓 ID가 주어지면 해당 티켓의 상세 정보를 조회한다.
   - 티켓 ID가 없으면 ITSM API v2가 문서화한 전체 목록 필터, 정렬, 커서 페이지네이션으로 검색·목록 조회를 제공한다.
   - 보이지 않는 티켓의 존재 여부를 추론하거나 노출하지 않는다.

3. **`ticket_write`**
   - 제목, 설명, 서비스, 영향도, 긴급도, 영향 범위, 발생 시각을 포함한 필수 정보와 계약상 허용된 선택 정보를 사용해 새 티켓을 등록한다.
   - 실행 전 Agent가 최종 등록 내용을 요약하고 사용자의 명시적 확인을 받는다.
   - 재시도나 대화 흐름 때문에 같은 요청이 중복 등록되지 않도록 한다.

4. **`ticket_update`**
   - 기존 티켓의 제목, 설명, 컴포넌트, 모델, 영향도, 긴급도, 영향 범위와 그 밖에 계약상 허용된 수정 필드를 변경한다.
   - 실행 전 Agent가 최종 변경 내용을 요약하고 사용자의 명시적 확인을 받는다.
   - 동시 수정이 감지되면 최신 변경을 덮어쓰지 않고 충돌을 알린다.

5. **검증과 문서화**
   - 실제 OpenAI API를 호출하지 않는 자동화 테스트로 세 도구, 계약, 권한 경계, 비밀정보 비노출 및 주요 오류 흐름을 검증한다.
   - 기존 테스트와 신규 테스트가 모두 통과해야 한다.
   - 구현 내용과 실행·테스트 방법을 README에 반영한다.
   - 대표 조회·등록·수정 시나리오에서 외부 ITSM 화면 전환이 0회임을 확인하고 기존 화면 방식보다 완료 시간이 줄었는지 측정한다.

### Should Have / Could Have

첫 릴리스에는 별도의 Should Have 또는 Could Have 항목을 두지 않는다. 세 도구와 공통 안전 경계가 함께 있어야 승인된 사용자 가치와 보안 조건을 충족하므로 모두 Must Have로 관리한다. 추가 편의 기능은 첫 릴리스 검증 후 별도 의도로 평가한다.

## 범위 밖 기능

- 티켓 삭제, 상태 전이, 담당자·담당 그룹 배정
- 첨부파일, 댓글, 작업 기록, 통계, 대량 내보내기
- ITSM API v2 계약이 허용하지 않는 필드 변경
- 새 Agent, 새 서비스, 새 화면 또는 기존 화면 재설계
- 다른 저장소의 ITSM 내부 코드 가져오기 또는 복사
- 샘플 티켓이나 특정 티켓 ID를 제품 지침 또는 도구 동작에 고정
- 기존 Assistant의 모델·reasoning 설정, 사용자 전환, 세션 및 대화 이력 동작 변경
- 별도 인프라, 신규 규제 체계, 새 SLA 또는 처리량 목표 도입

## 사용자 가치 흐름

1. 사용자가 현재 Assistant에서 조회·등록·수정 의도를 말한다.
2. Assistant가 작업에 필요한 업무 정보를 확인한다.
3. 조회는 즉시 권한 범위 안의 결과를 반환한다.
4. 등록·수정은 실행 예정 내용을 요약해 사용자에게 명시적 확인을 요청한다.
5. 사용자가 확인하면 현재 사용자 권한으로 ITSM이 요청을 처리한다.
6. Assistant가 업무 결과 또는 안전하게 정리된 오류와 다음 행동을 알려준다.

텍스트 흐름: `사용자 요청 → 정보 확인 → (조회 결과 | 등록·수정 요약 및 확인) → ITSM 권한 판정과 처리 → 안전한 결과 안내`

## 우선순위와 전달 순서

범위는 의존성과 위험을 먼저 줄이는 순서로 전달한다.

1. 공통 보안·권한·오류 경계를 확정한다.
2. 부작용이 없는 조회와 상세 확인 흐름을 완성한다.
3. 명시적 확인과 중복 방지를 포함한 등록 흐름을 완성한다.
4. 명시적 확인과 동시 수정 보호를 포함한 수정 흐름을 완성한다.
5. 전체 회귀·보안·사용자 가치 검증과 README 갱신을 완료한다.

이 순서는 `intent-backlog.md`의 의존성과 일치하며, 앞 단계의 안전 경계를 뒤 단계가 공통으로 사용한다.

## 의존성과 제약

- 연동 계약의 기준은 `docs/itsm/integration-guide.md`와 `docs/itsm/openapi.json`이다.
- 티켓 업무는 ITSM API v2를 HTTP로 호출하며, 현재 서버 측 세션과 사용자 위임 권한이 유효해야 한다.
- 권한 및 가시성 결과는 ITSM API가 최종 결정한다.
- 등록 필수 정보, 수정 허용 필드, 목록 필터·정렬·페이지네이션은 계약 범위를 벗어나지 않는다.
- 등록에는 중복 방지, 수정에는 동시 변경 보호가 필요하다.
- 고정 납기는 없고 계약·보안·회귀 품질 기준 충족을 우선한다.
- 현재 확인된 No-Go 차단 항목은 없다.

## 성공 및 수용 경계

다음 조건을 모두 만족할 때 첫 릴리스 범위가 완료된 것으로 본다.

- Agent에 사용자에게 노출되는 티켓 도구가 `ticket_read`, `ticket_write`, `ticket_update` 정확히 세 개다.
- `ticket_read`가 ID 상세와 문서화된 전체 목록 검색 조건을 지원한다.
- `ticket_write`와 `ticket_update`가 사용자에게 최종 내용을 요약하고 명시적 확인 후에만 데이터를 변경한다.
- 세 도구가 현재 로그인 사용자의 권한과 티켓 가시성을 벗어나지 않는다.
- 비밀정보가 모델 입력, 결과, 로그, 오류 응답에 노출된 사례가 없다.
- 등록 중복과 수정 충돌을 안전하게 처리한다.
- 실제 OpenAI API 호출 없는 신규 자동화 테스트와 기존 전체 테스트가 통과한다.
- 기존 사용자 전환, 세션, 대화 이력, 고정 모델 설정, 화면과 API에 회귀가 없다.
- 대표 조회·등록·수정 시나리오를 외부 ITSM 화면 전환 0회로 완료한다.
- 동일한 대표 시나리오를 기존 화면과 Assistant에서 각각 3회 수행했을 때 Assistant의 시나리오별 중앙 완료 시간이 더 짧다.
- README가 기능, 설정, 실행 및 테스트 방법을 설명한다.

## 가정과 후속 검증

- 기존 애플리케이션 설정과 배포 구조 안에서 기능을 제공할 수 있다는 가정을 설계 단계에서 확인한다.
- 기존 Python/FastAPI, Agents SDK, HTTP 클라이언트와 테스트 패턴을 팀이 유지할 수 있다는 가정을 팀 구성 단계에서 확인한다.
- 비밀정보 비노출, 토큰 만료, 등록 중복, 수정 충돌, 권한 없는 티켓의 비노출, 호출 제한과 장애 처리는 설계·구현·테스트에서 증거를 남긴다.
- 사용자 완료 시간 비교는 동일 입력과 동일 시작·종료 조건을 사용해 기록한다.
