## 역량 공백 분석

### 현재 확인된 공백

상시 인력 또는 외부 파트너로 보완해야 할 공백은 확인되지 않았다. 기존 프로젝트에 필요한 기술 기반과 테스트 패턴이 있고, AI-DLC 역할 구성이 개발·아키텍처·보안·품질 관점을 포함한다.

### 조건부 자문이 필요한 영역

| 조건 | 자문 대상 | 해소 기준 |
|---|---|---|
| ITSM 문서 간 의미가 불명확하거나 실제 운영 정책과 다름 | ITSM 운영 책임자 | 계약 의미와 허용 동작이 문서로 확정됨 |
| 위임 권한 또는 오류 데이터 처리에 기존 사내 정책 해석이 필요함 | 내부 보안 담당자 | 허용·금지 경계와 검증 방법이 확정됨 |
| 사용자 성과 비교의 측정 환경이 달라 결과가 왜곡될 수 있음 | 제품 책임자·품질 책임자 | 동일 입력과 시작·종료 조건이 합의됨 |

## 공백 예방과 역량 공유 계획

- 아키텍처, 개발, 보안, 품질 역할은 공통 안전 경계를 함께 검토하여 결정이 한 역할에만 남지 않게 한다.
- 계약 해석과 중요한 보안 결정은 저장소 산출물에 근거와 영향을 남긴다.
- 테스트는 기능 구현 뒤 일괄 확인하는 것이 아니라 각 능력의 완료 조건으로 함께 관리한다.
- 등록 중복, 수정 충돌, 권한 없는 티켓 비노출, 비밀정보 비노출은 해당 능력 담당자와 품질 역할이 공동으로 검증한다.
- README에는 운영자와 후속 개발자가 기능을 재현할 수 있는 실행·테스트 정보를 남긴다.
