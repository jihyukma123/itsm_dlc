# ITSM 티켓 도구 이해관계자 맵

## Stakeholder Map

| 이해관계자 | 구분 | 주요 관심사 | Source |
|---|---|---|---|
| 제품 책임자 | 최종 의사결정자 | 첫 버전의 범위와 우선순위, 세 가지 티켓 기능의 성공 기준 | [Q3] [Q5] |
| ITSM 운영팀 | 영향자 | 기존 권한 및 티켓 가시성 규칙을 유지하는 ITSM 연동 | [desc] [Q5] |
| 보안 담당자 | 영향자 | 토큰과 secret 등 비밀정보의 비노출, 기존 사용자 권한 유지 | [desc] [Q3] [Q5] |
| 일반 사내 사용자 | 주요 사용자 | 별도 화면 이동 없이 대화 안에서 티켓 업무 완료 | [Q1] [Q2] |
| 서비스 데스크 담당자 | 주요 사용자 | 반복적인 티켓 조회·등록·수정 작업 시간 단축 | [Q1] [Q2] |

## Decision-makers vs. Influencers

- 제품 책임자가 첫 버전의 범위와 우선순위를 최종 결정한다. [Q5]
- ITSM 운영팀과 보안 담당자는 기존 운영 규칙과 보안 제약이 반영되도록 의사결정에 영향을 준다. [desc] [Q5]
- 일반 사내 사용자와 서비스 데스크 담당자는 기능의 직접적인 수혜자이며, 역할별 접근 가능 범위는 ITSM API가 판단한다. [desc] [Q2]

## Communication Requirements

각 단계의 검토 외에 별도의 정기 보고나 추가 결과 보고는 요구하지 않는다. [Q6]
