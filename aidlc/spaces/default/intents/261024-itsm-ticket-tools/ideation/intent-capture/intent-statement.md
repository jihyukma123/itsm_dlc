# ITSM 티켓 도구 기능 의도

## Problem Statement

기존 ITSM Assistant 사용자는 대화 중 티켓을 조회·등록·수정하려면 별도 ITSM 화면으로 이동하거나 반복 입력을 해야 한다. 이번 작업은 현재 Assistant 안에서 이 세 가지 티켓 업무를 완료하고, 반복 작업 시간을 줄이며, 로그인 사용자의 기존 ITSM 권한 안에서 자연어 요청을 안전하게 처리하는 데 목적이 있다. [desc] [Q1] [Q4]

## Target Customer

주요 사용자는 기존 ITSM Assistant를 사용하는 일반 사내 사용자와 서비스 데스크 담당자다. 두 사용자군 모두 대화 안에서 티켓 업무를 수행하되, 역할별 권한과 티켓 가시성 판단은 기존 ITSM API에 맡긴다. [desc] [Q2]

## Success Metrics

- 대표 조회·등록·수정 시나리오 3종 모두를 대화 흐름 안에서 외부 ITSM 화면 전환 0회로 완료하고, 이를 자동화된 인수 시나리오로 검증한다. [Q1] [Q3] [review-04 R-01]
- 대표 조회·등록·수정 시나리오를 동일한 입력 조건으로 기존 ITSM 화면 방식과 Assistant 방식에서 각각 3회 수행했을 때, Assistant 방식의 시나리오별 중앙 완료 시간이 기존 방식보다 짧아야 한다. [review-04 R-04] [feasibility change request]
- `ticket_read`, `ticket_write`, `ticket_update`가 승인된 ITSM API 계약에 맞게 각각 조회·등록·수정을 정확히 수행한다. [desc] [Q3]
- 기존 사용자 전환, 세션, 대화 이력, 고정 모델, 화면 및 API 동작에 회귀가 없다. [desc] [Q3]
- 액세스 토큰, 클라이언트 secret, OpenAI API key가 모델 입력, 도구 결과, 로그 또는 오류 응답에 노출되는 사례가 0건이다. [desc] [Q3]
- 실제 OpenAI API를 호출하지 않는 신규 자동화 테스트와 기존 테스트가 모두 통과한다. [desc] [Q3]

## Initiative Trigger

기존 Assistant에 티켓 처리 기능이 없어 사용자가 대화 흐름을 벗어나야 하는 기능 공백을 해소하는 것이 이번 작업의 직접적인 추진 계기다. [Q1] [Q4]

## Initial Scope Signal

- 워크플로에서 선택된 범위는 `feature`이며, 이는 workflow-selected 범위다. [scope]
- 첫 버전은 기존 Agent와 Runner, 서버 측 사용자 세션 및 사용자 위임 토큰을 활용해 티켓 조회·등록·수정 기능을 추가한다. [desc] [Q7]
- 티켓 삭제, 첨부파일·댓글·작업 기록, 새 에이전트나 별도 서비스, 기존 화면 재설계나 새 화면은 첫 버전에서 제외한다. [Q7]

## Review Finding Resolution

- **R-01 — 사용자 성과 측정 부족:** 외부 ITSM 화면 전환 0회와 시나리오별 완료 시간 감소를 성공 기준에 포함했다.
- **R-02 — 확인되지 않은 “조작 단계 1단계 감소”:** 사용자 확인이 없던 임계값과 단계 수 측정 기준을 제거했으며 성공 기준으로 사용하지 않는다.
- **R-03 — 확인되지 않은 “정량 임계값 유보”:** 사용자 선택으로 뒷받침되지 않던 유보 결정을 제거하고 실제로 검증 가능한 완료 시간 비교 기준을 채택했다.
- **R-04 — 반복 작업 시간 단축 측정 누락:** 동일 조건에서 조회·등록·수정 시나리오를 각 방식으로 3회 수행하고, Assistant 방식의 시나리오별 중앙 완료 시간이 기존 화면 방식보다 짧아야 한다는 기준을 추가했다.
